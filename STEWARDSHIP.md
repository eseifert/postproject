# Stewardship

PostProject is currently stewarded by the owner and maintainers of
[`postproject-org/postproject`](https://github.com/postproject-org/postproject). Maintainer
authority is represented by repository merge and release permissions. Design,
compatibility, and release decisions are recorded publicly in issues, pull
requests, architecture decision records, the changelog, and acceptance reports.

The project is maintained on a best-effort basis and offers no support or
security-response service-level agreement. Bug and design reports should use
the GitHub issue tracker. Sensitive vulnerability reports should use GitHub's
private security-advisory channel when available rather than a public issue.

Before an explicit stability milestone, consumers should pin an exact release
or commit. API, ABI, schema, CLI, and binding changes may be intentional when
they improve the architecture; coordinated tests, documentation, and changelog
entries are still required.

If current stewardship stops, the dual MIT or Apache-2.0 license permits the
source and its history to be continued independently. Active contributors may
propose a transfer to a new maintainer or community organization. Any transfer
of release credentials, package names, the repository, or `postproject.org`
must be announced publicly and completed before a successor publishes under
the existing project identity. Until that happens, forks must not imply that
they are official PostProject releases.
